# TeachMate 教师对话核心改造方案

日期：2026-09-30。状态：代码调研与方案已完成，以下功能改造尚未实施。

统一排期与进度见[后续开发任务总表](TEACHMATE_NEXT_DEVELOPMENT_TASKS.md)。教师专项/分层练习、教案协作、作答反馈、复测和学生互动均已纳入后续范围；本文件继续作为对话核心的技术设计，原 P0–P3 对应总表 A、B、G 的相关任务。

本方案补充 1.0 升级计划，并调整下一阶段优先级：先解决教师连续交流、理解上下文、按需取证和第三方模型适配，再扩展学生端互动。源码版本继续为 1.0.0；未经用户要求不生成安装包。

## 1. 产品目标与责任划分

目标是让教师可以自然地讨论学生、教学目标和材料；AI 判断问题的含义，选择直接回答、读取事实、比较、追问或生成成果。姓名识别是验收场景之一，不能用一组新的关键词分支代替整体改造。

| 交给 AI 的判断 | 由程序可靠执行 |
| --- | --- |
| 理解本轮意图、承接指代、组织回答 | 保存会话焦点、教师纠正和运行快照 |
| 决定是否查资料、查哪些维度 | 验证访问范围、解析身份、查询和计算 |
| 解释证据、提出可能错因与教学方法 | 返回有来源的事实、缺失情况和数据时间 |
| 决定追问、回答长度与呈现方式 | 参数校验、调用去重、预算和超时控制 |
| 草拟材料和修改建议 | 保存、版本管理及既有正式数据写入规则 |

默认采用一个对话模型加少量业务工具。没有为日常聊天另建规划、执行、审查多个模型的必要。结构化的是工具参数、业务状态和正式成果契约，普通回复保持自然语言。

## 2. 现有代码中的证据

以下是对当前工作区代码的静态核查，不是对已安装应用或真实 API 的复现结论。

| 现象 | 源码入口 | 影响 |
| --- | --- | --- |
| 普通对话也继承“结论、主要发现、证据、建议、局限”的强制格式 | `backend/app/agent/run_executor.py::_build_harness_system_prompt`；`orchestrator.py::_build_system_prompt` | 简短追问也容易变成报告 |
| 分析包不仅给事实，还给诊断和行动建议；提示词要求直接提交报告并禁止单项查询 | `run_executor.py::_build_harness_system_prompt`；`analysis_packet.py` | 模型解释和核查空间有限；节省调用的策略过度约束复杂问题 |
| 输入映射使用 `allow_student_names=True`，系统提示仍要求匿名，Bridge 又强制把姓名换为代号 | `run_executor.py`；`privacy.py`；`education_bridge/bridge_cli.py::_Anonymizer.sanitize` | 同一学生在问题和工具结果中的表示不一致；关闭一个脱敏开关不足以接通链路 |
| 后端按姓名绑定学生只接入复习计划入口；普通聊天未接入该解析器 | `routers/agent.py::_resolve_review_plan_student`、`send_message` | 能在一个入口找到人，不代表自由聊天也能找到 |
| 成绩工具只能查询服务端已经绑定的单个学生 | `education_bridge/bridge_cli.py::_tool_student_scores` | 无法自然完成临时点名或两人比较 |
| 名称映射以姓名作为单值键；匿名序号按本轮名单生成 | `privacy.py::register_name`；`services/agent_analysis/identity_dict.py` | 同名和范围变化需要专门处理，不能把姓名视为唯一身份 |
| 调度器按 AnalysisRun 取范围，但 Harness 中身份词典、分析包和 Bridge 又读取 AgentSession 范围 | `services/agent_runs/scheduler.py::build_run_scope`；`run_executor.py::_execute_harness_run_managed` | 本轮解析出的学生或继承的考试可能没有进入实际执行环境，需集成回归验证 |
| 提示构建函数的 `db_session` 用于数据库查询，同时又在复习计划分支读取 `.student_id`；调用处传的是数据库 Session | `run_executor.py::_build_harness_system_prompt` | 数据库连接与业务范围混用；拆开参数并补回归测试 |
| 两种运行路径的普通聊天工具清单不同 | `registry/capabilities.py::GENERAL_CHAT_READ_TOOLS`、`GENERAL_CHAT_MANAGED_READ_TOOLS` | 同一自然语言请求可能随运行路径表现不同 |

已经存在可复用的基础：普通聊天自然语言输出、只读工具、滚动摘要、输入输出预算、正式报告证据校验、运行快照和教学任务上下文。改造应连接并修正这些模块，避免另建一套平行 Agent。

## 3. 参考项目及适配方式

下面区分上游实现与 TeachMate 的设计建议；不表示已经移植源码，也不以项目宣传代替效果验证。链接核查于 2026-09-30，主分支内容可能继续变化。

- **DeepTutor**：[工具分发代码](https://github.com/HKUDS/DeepTutor/blob/main/deeptutor/core/agentic/tool_dispatch.py)通过服务端补齐工具参数、处理缺参、合并重复调用，并表达追问暂停状态；[对话循环](https://github.com/HKUDS/DeepTutor/blob/main/deeptutor/core/agentic/loop.py)承接工具结果与暂停恢复。TeachMate 借鉴“模型决定下一步、程序提供可信执行上下文”，不照搬完整多 Agent 系统。
- **Pydantic AI**：[UsageLimits 源码](https://github.com/pydantic/pydantic-ai/blob/main/pydantic_ai_slim/pydantic_ai/usage.py)区分请求、工具次数、单次输入与累计用量限制。TeachMate 借鉴分层预算；响应后的用量检查无法撤回已经产生的费用，还需请求前估算和输出上限。
- **Presidio**：[可逆替换示例](https://github.com/data-privacy-stack/presidio/blob/main/docs/samples/python/pseudonymization.ipynb)由客户端持有实体映射，供替换和还原。TeachMate 借鉴本地映射原则，实际键必须是学生实体 ID，不能直接照搬按姓名字符串作为唯一键的示例。
- **LiteLLM**：[适配基类](https://github.com/BerriAI/litellm/blob/main/litellm/llms/base_llm/chat/transformation.py)与[不支持参数处理文档](https://docs.litellm.ai/docs/completion/drop_params)展示了按模型能力处理请求的方式。TeachMate 借鉴能力档案和参数适配，不因此新增网关依赖；工具、权限或成果契约不能为了兼容而静默删除。

## 4. 对话执行方式

```text
教师输入 + 当前教学任务
          ↓
本地解析明确实体，读取会话焦点，冻结本轮范围
          ↓
短系统规则 + 必需上下文 + 少量可用工具 → 模型
          ├─ 直接回答 / 编辑文字
          ├─ 身份或意图不明确 → 简短追问 → 用户回复后续接
          └─ 需要事实 → 校验工具参数与范围 → 紧凑结果 → 模型回答
                                                               ↓
                                 事实引用检查、姓名本地还原、展示
```

第一次模型请求同时承担理解意图与选择工具，不为每句话先增加一次“分类/规划”调用。常用工具按当前权限和数据可用性开放；少用能力可按需发现。工具数量控制不能依赖少量汉字关键词来阻止教师合理请求。

对话模式和正式成果模式共用状态与证据。快捷按钮成为可编辑的任务提示；问“这个建议为什么适合他”不必重新生成整份报告。只有需要保存正式报告、生成材料等成果时才应用对应输出结构。

事实包保留本地核算的成绩、分布、题目和数据缺口；预设诊断、风险阈值与建议标为规则线索，不冒充确定错因。AI 可以依据问题选择进一步取证，也可以提出多个解释，并说明可通过什么课堂观察区分它们。教师的“这部分还没教过”必须修正后续解释。

## 5. 身份与连续上下文

采用“本地学生解析器 + 对话实体表 + 本轮身份快照”，在首次外发前完成可确定的匹配。无需先让外部 AI 看不懂姓名，再额外调用一次模型。

1. 在已授权学期和班级范围内，规范化输入后匹配完整姓名、学号、已确认别名。学号只在本地作查询键，数据库学生 ID 才是实体主键。
2. 唯一精确匹配绑定实体；同名返回班级等最少必要区分信息，教师选择后续接原问题。错别字、拼音和简称只能生成候选，不自动认定为本人；处理姓名嵌套和普通词同名误匹配。
3. 多人提及保存为实体列表，支持比较。“他/她”仅在焦点唯一时承接；“他们”使用明确的最近集合；不确定则追问。切到“全班”清除个人焦点，但不扩大授权范围。
4. 讨论焦点不等于访问权限。在已授权班级内换一个人，不应强制重开聊天；跨越授权范围则通过明确的范围选择处理。
5. 使用会话内稳定、不包含真实学号的引用标识。输入、历史、工具结果和答案使用同一实体表，本轮冻结映射，重载和历史展示使用相应快照；禁止每轮重新排序编号后猜测旧编号含义。
6. 工具可接受经过解析的实体引用；服务端把它映射为本地学生 ID，再校验班级、考试与数据范围。模型提供的原始数字 ID 不直接成为查询权限。
7. `matched / ambiguous / not_found / out_of_scope / data_missing` 分开处理。“有这个学生但没有本次考试成绩”与“名单没有此人”不能混为一谈，也不能用风险名单判断学生是否存在。

隐私模式要全链路一致。严格模式由本地替换姓名，答案本地还原；教师姓名可见模式可以保留姓名，但仍去掉电话等无关字段。采用哪种模式不应影响实体解析的正确性。默认模式沿用现有产品选择，先修一致性，不能通过全局关掉过滤来掩盖身份链路问题。

未知姓名不能靠简单名单替换保证识别率：严格模式应对未解析的人名候选进行本地提示或替换，不宣称规则可以发现所有个人信息。姓名同名情况保存候选集合，不覆盖另一人的映射。

## 6. 稳定性、准确性与成本共同控制

| 维度 | 具体做法 |
| --- | --- |
| 稳定性 | 参数结构与值域校验；服务端注入范围；只读查询去重；错误分型；取消、超时和断线状态持久化；恢复时不重复执行已完成的操作 |
| 准确性 | 分数、排名、比例由本地计算；工具返回来源、考试/班级/人员、数据时间和缺失信息；重要结论区分事实、推断和建议；引用 ID 验证不等于整段语义已被证明 |
| 交互质量 | 问题可回答的部分先回答；真正影响判断时才追问；工具空结果不阻断一般教学建议；避免每轮机械列出同一套局限 |
| Token | 相关实体与材料片段按需进入上下文；保存教师约束、纠正、焦点、已取证摘要，不重传整班名单或所有报告；去重和缓存必须带数据版本及范围键 |
| 运行预算 | 分别限制单次输入、累计请求、工具尝试次数、累计用量与时长；失败和修复同样计入预算；在达到上限前留出回答余量 |
| 第三方 API | 能力档案记录工具调用、结构化输出、流式、推理参数、上下文及用量报告能力；不支持工具的模型仍能普通聊天，数据任务走明确的本地取证路径或说明缺失能力 |

建议的初始实验档位：简单交流争取一次模型请求；常规查数争取“选择工具 + 回答”两次；复杂比较允许有限追加取证。次数是评测起点，不作为新的固定业务流程。沿用现有预算上限，在测量后调整，不先统一增加轮数、温度或推理强度。

工具失败提供可恢复状态，参数错误最多有限修正；网络重试退避且累计计费，重复失败后用已有事实给部分回答。不能把成绩查询失败转写为“学生成绩为零”，也不能因模型缺少工具能力便伪称已查数据库。

上下文裁剪不能删掉实体对应关系、教师纠正、范围约束与关键证据；可删旧工具明细和重复正文。摘要保留来源与不确定性。既有本地任务上下文和滚动摘要继续复用，不默认增加另一次总结模型调用。

## 7. 实施顺序与交付门槛

所有阶段目前均待实施；只完成了上述源码审查和设计。开关、迁移与降级要保证已有聊天和报告可读取。

| 阶段 | 工作 | 验收门槛 |
| --- | --- | --- |
| P0：统一执行事实来源 | 统一 AnalysisRun 范围；拆开数据库连接/范围参数；统一隐私模式与工具清单；补实际 Harness 路径回归 | 会话与本轮范围不同仍查对人；姓名模式一致；已有报告契约不退化 |
| P1：自然对话核心 | 分离普通对话/正式成果提示；本地解析器；稳定实体表和持久化焦点；自然追问续接；有范围约束的点名查询与比较 | 点名、指代、换人、同名、多轮纠正都能继续原会话；一般教学问答不强制报告格式 |
| P2：自主取证与模型兼容 | 事实包与预设解释分离；按需只读工具；紧凑证据结果；错误恢复；Provider 能力适配 | AI 可选择查什么而不能越权；工具不支持、空数据和超时均有正确反馈 |
| P3：测量与调优 | 对话回放、真实模型对比、用量分项统计、缓存失效与裁剪测试 | 在身份和事实准确性不退化前提下比较自然度、完成率、时延和成本；达标后才扩大默认启用范围 |

P0/P1 优先于新增学生端复杂 Agent。每阶段独立开关、记录差异与回退方式；不通过只改提示词就宣布整套重构完成。

## 8. 验收场景与评估方法

| 教师输入/情况 | 应有行为 |
| --- | --- |
| “张三这次数学怎么退步了？” | 本地定位人和考试；没有可比前次成绩时不承认“退步”已被证实 |
| “那他第 5 题呢？” | 沿用同一学生与考试，定向查题，不重跑完整诊断 |
| “和李四比呢？” | 保留两人对象，在授权范围内比较，不要求另建会话 |
| “张三和李四都适合这个练习吗？” | 保留多人集合，分别解释适配依据 |
| 两个同名学生、错字、昵称、姓名为普通词 | 同名/不确定时澄清，不任意命中；已确认别名可复用 |
| “学号 20260001 的同学” | 本地学号查人，后续使用同一实体引用 |
| 学生存在但该考试没成绩 | 准确说明缺的是什么，可继续一般教学讨论 |
| “这章我还没教” | 修正之前的归因，不继续认定学生已经学过但未掌握 |
| “说短一点”“只改第二题”“给我三种讲法” | 接续当前材料或话题，按要求回应，不重生成整份报告 |
| 未选考试，问“怎样讲清分数除法？” | 直接提供教学建议，不因无考试而拒答 |
| 数据返回空、缺参数或超时 | 区分原因；必要时有限修复或追问，保留可回答部分 |
| 越界引用、伪造学生 ID、工具结果含指令 | 保持服务端范围和指令边界，不把结果文本当系统指令 |
| 更换班级、重启、并发运行、学生名单变化 | 人物不串号；历史答案还原正确；缓存不返回旧范围数据 |
| 超过预算、取消或重连 | 不无限重试；能说明已完成和未完成部分 |

先用合成学生数据和模拟 Provider 建立可重复测试，覆盖姓名/范围/证据等确定性行为；再用固定同一组教师对话、相同模型和参数比较改造前后。复杂任务至少重复多次，避免单次回答偶然性。

离线门槛：固定测试集中不出现串人、越权或将缺失值当真实成绩，原有正式报告与材料保存测试通过。模型评测另记可核实数字错误率、无依据断言、任务完成率、非必要追问次数及教师盲评的自然度；有限测试通过不等于生产中绝无错误。

Token 统计拆分系统提示、工具定义、历史、材料、工具结果和输出；同时记录真实 Provider usage、重试、缓存命中、首字/完成时延的中位数与高分位。优化目标是每个成功完成任务的成本，不是只让回答更短。用量缺失标为未知，估算不冒充真实计费。

本轮未调用真实付费模型，未测得节省比例，也未验证真实课堂教学效果。当前完成物是可执行的设计和验收基线要求，功能实现进度按上表后续更新。
