# TeachMate 工程改造基线

适用范围：本地单教师桌面版。应用进程仍以 FastAPI 管理教学事实，以 SQLite 和附件目录持久化，以 Harness 执行模型回合。外部插件只能经受控接口访问教学数据。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 教学数据服务 | 学期、考试、试卷版本、逐题成绩、来源、完整度和确定性统计 | 生成教学解释 |
| 文档服务 | 原件校验、分页提取、OCR、质量标记、待校对结果 | 直接写正式成绩 |
| 任务服务 | 持久状态、进度、取消、幂等、重试和恢复 | 解释模型输出 |
| 教学工具入口 | 作用域与参数检查、匿名化、证据登记 | 另建一套成绩计算 |
| 模型运行层 | 管理 Harness 会话及模型事件 | 决定成绩或资料是否成为正式事实 |
| 报告服务 | 输出校验、数据版本快照、教师确认、导出 | 修改原始资料 |

成绩页面、学生诊断、普通聊天和外部插件应调用同一教学数据服务。模型不得补算或猜测缺失分数。未确认的文件识别结果只能作为标明状态的参考材料；进入正式成绩表需要校验与教师确认。

## 本轮已接通的纵向链路

1. `student_score_details.py` 按同一试卷版本返回总分、题型小计、逐题成绩、来源、录入完整度和总分核对结果；学生诊断和 Education Bridge 共用它，另提供只读 HTTP 接口。
2. 普通聊天新增受当前会话考试和学生范围约束的 `get_student_scores`。模型只能给出可选题号，不能提交学生 ID 或考试 ID。Bridge 继续匿名化并登记证据。
3. MONI 同步在首次小分读取为空时仍按学生补读，且在本地校验返回行的学生 ID，避免把服务端忽略过滤条件的结果错误合并。
4. PDF 逐页记录扫描页。配置并启用视觉识别时，后台渲染扫描页并识别；识别条件不具备或部分页失败时保留已提取的页面并标为 `pending_ocr`，可重新提交同一任务。
5. 前端持续跟踪尚未结束的解析任务。超过单次等待窗口不会把后台任务误判为失败；去重上传也不会把待 OCR 附件直接标为可发送。
6. 新的 Harness 分析运行保存排队、数据准备、模型调用、报告修复和总耗时，便于找出慢请求的主要阶段。
7. 新报告的事实指纹包含试卷结构、总分及逐题分数；读取运行状态时，能标明已生成报告的数据是否过期。旧版快照明确返回 `unknown`，避免误判。

## 部署与排查

- 扫描 PDF 自动识别需要 `pdftoppm` 在进程可执行路径中、视觉识别功能已开启、视觉模型及密钥已配置。环境变量部署可使用 `AGENT_VISION_ANALYSIS_ENABLED`、`AGENT_VISION_PROVIDER`、`AGENT_VISION_MODEL_NAME`、`AGENT_VISION_API_KEY_ENV`；桌面版也可使用现有模型设置。每份文件最多自动处理 20 个扫描页，超出后提示拆分。
- 解析结果位于附件的 `metadata_json.parsed`：`pages` 保留逐页结果，`parse_metadata.ocr_pages` 是待识别页，`parse_metadata.ocr_unavailable_reason` 是待处理原因。配置恢复后再次发起解析会重排待 OCR 任务。
- 学生成绩可通过 `GET /api/v1/exams/{exam_id}/students/{student_id}/score-details` 核对。`detail_status` 和 `total_reconciliation` 分别表示逐题数据完整度与小分合计和总分是否相符；若接口仍无小分，应先检查学校端是否提供逐题记录、同步任务错误和试卷版本对应关系。
- 运行详情的 `timings_ms` 供定位慢请求，`report_freshness` 供识别报告是否沿用旧成绩。建立同设备、同考试、同模型的基线后再设定性能目标。

## 后续实现顺序

1. **数据一致性：** 让现有逐题列表接口与统一成绩服务使用同一试卷选择规则；为导入批次保存预期题数、实际题数和缺失原因。将新报告已具备的过期标记展示在教师端。
2. **文件质量：** 增加 PDF 密码保护、乱码、表格跨页、OCR 低置信区域的明确状态；完成分页重试。对纸质成绩表，先生成可校对的结构化草稿，再写正式成绩。
3. **执行效率：** 用已有耗时字段采样真实请求。明确数值查询优先走确定性接口；交互、OCR、批量分析分别限流。只缓存以数据修订号为键的结果。
4. **交互体验：** 把后台任务进度保存并可在页面恢复；普通聊天在完成隐私检查后分段展示文本；正式报告保留校验门，不直接公开未经校验的模型正文。
5. **边界收敛：** 让路由只做鉴权和参数转换，Education Bridge 只做受控工具适配；逐步移除保留期过后的旧 Agent 生产路径。保持跨语言工具名单和参数契约的自动校验。

## 验收场景

- 文字、扫描和混合 PDF 在新安装的 Windows/macOS 环境中可识别或给出具体待处理原因；不能把空白识别结果标为完成。
- 同一学生的第 18 题分数、题型小计与完整度，在 HTTP 接口、聊天工具和学生诊断里一致。
- 首屏小分为空、接口分页、学生 ID 字段变化时，导入结果要么完整，要么明确标出缺口。
- 40 人批量诊断中单人失败后可只重试失败部分；聊天请求不会被 OCR 或批量任务长期占满。
- 新的 Harness 运行能定位排队、数据准备、模型调用及报告修复耗时；性能目标依据同设备同样本的基线制定。

## 当前限制

OCR 自动完成依赖已启用的视觉识别配置和可用的 PDF 页面渲染组件；未配置时附件保持待 OCR。现有试卷录入入口与聊天附件仍分别维护页面渲染路径，后续应合并。结构化成绩表识别、教师端报告过期提示、完整的安全正文流式展示和批量任务分级调度尚未完成。
