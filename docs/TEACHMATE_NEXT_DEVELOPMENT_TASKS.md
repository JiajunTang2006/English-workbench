## 2. 产品原则

1. AI 负责理解意图、决定是否查询、解释证据、提出方案和自然交流；程序负责实体匹配、权限、事实计算、保存与预算。
2. 普通聊天保持自由表达；工具参数与业务结果结构化。快捷按钮是入口，不把教师语言限制成固定命令。
3. 成绩、题目表现、教师观察与推测分开。单次低分不直接定性为知识薄弱或学习态度问题。
4. 教师纠正、已教内容、课时与作业要求进入后续生成和修改；不要求每轮重新填写。
5. 复用已有教学任务、材料版本、反馈和对话运行机制；默认一个对话模型加少量工具，按需调用。
6. 专项练习先服务教师，可打印、可调整；学生互动复用同一套题目和反馈数据，不另建重复的内容系统。
7. 准确性、自然度、稳定性与成本同时验收。Token 优化以成功完成教师任务的成本衡量，不能只缩短答案。

## 5. 数据与模块衔接要求

实现时优先扩展以下已有模块；具体迁移字段在对应任务开始时设计，不预设本表已定义最终数据库结构。

- 对话与运行：`backend/app/routers/agent.py`、`agent/run_executor.py`、`agent/orchestrator.py`、`services/agent_analysis/`、`services/agent_runs/`。
- 身份、工具与适配：`agent/privacy.py`、`services/agent_analysis/identity_dict.py`、`agent/education_bridge/`、`agent/registry/`、`agent/providers/`。
- 教学任务与材料：`models/teaching_entities.py`、`schemas/teaching.py`、`services/teaching.py`、`routers/teaching.py`、`workbench-assets/teachmate-tasks.js`。
- 新增练习域需要连接：任务对象 → 学习目标 → 题目版本 → 作答 → 提示事件 → 反馈/教师修正 → 新题复测。学生会话引用这条链，不能复制一份独立成绩事实。
- 教案与练习共同使用稳定的目标/材料/题目引用。编辑题目后的答案、提示、已布置练习和历史作答必须遵循明确版本规则。
- AI 生成草稿、教师采用、学生已作答、正式成绩是不同状态。保留现有写入控制；不因增设自由对话而混用这些状态。

## 6. 完整交付的验收故事

使用合成学生与固定教学材料先完成可重复验证，再安排真实使用走查：

1. 教师说“看看张三这次为什么错得多”，系统找到正确学生和考试，区分已有事实与可能原因。
2. 教师补充“这部分还没教”，AI 修正判断；继续问“李四呢”，不需要重新创建对话。
3. 教师要求“给他们各出 5 道题，先基础再迁移”，得到对象明确、目标一致、答案可核对的个人练习；也能改成分层小组练习。
4. 教师说“第二题太难，换一道，其他不变”，系统保留其余题目，更新对应答案/提示并保存版本。
5. 教师核对与修改练习，另存新版本；D 阶段的自动完整教案不在本轮范围。
6. 教师打印学生练习，课堂或纸面完成后手工录入/导入逐题作答，注明提示使用或答案查看；F 阶段的学生在线入口不在本轮范围。
7. 系统提供可核对的反馈，记录提示使用；教师修正错误判断后安排同目标的新题复测。
8. 教师能看到独立作答与提示后完成的差异，并据此继续调整教案。全流程可查看调用成本、失败与数据来源。
