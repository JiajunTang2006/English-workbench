# 英语教学工作台前端视觉审计报告

> 审计日期：2026-08-29  
> 范围：`workbench.html` + `workbench-assets/*.css` + 实际渲染截图  
> 结论：整体功能可用，但视觉体系尚未收敛；最大问题是 **三套设计 token 混用** 导致 WorkBench 与 TeachMate 互相"染色"，其次是组件级样式离散、响应式断点不统一、空状态处理粗糙。

---

## 一、数据层面的问题（静态扫描）

### 1.1 三套色板并行，未做统一

| 文件 | 主背景/表面 | 主强调色 | 辅助灰 | 说明 |
|------|-------------|----------|--------|------|
| `workbench-app.css` | `#f4f3f0` 暖米灰 | `#050038` 深紫黑、`#2563eb` 亮蓝 | `#6b6786` 紫灰 | 旧 WorkBench 风格 |
| `teachmate.css` | `#f7f8fa` 冷灰 | `#1c1c1e` 近黑、`#ffd02f` 品牌黄 | `#e0e2e8` 中性灰 | Miro 风格 |
| `workbench-enhancements.css` | `#f4f6fb` 淡蓝灰 | `#1e1e2e` 近黑 | `#66708f` 蓝灰 | 第三套蓝调体系 |

- 三个 CSS 文件共出现 **352 个唯一 hex 颜色**（`workbench-app` 171、`teachmate` 166、`enhancements` 15）。
- 同一概念（背景/边框/次级文字）在不同文件使用不同变量名：`--bg`、`--tm-bg`、`--wb-sidebar-width` 等，无统一 alias。

### 1.2 变量重复声明严重，覆盖顺序脆弱

- `workbench-app.css` 中 84 个变量有 **46 个被重复声明**（如 `--primary` 3 次、`--risk-accent` 4 次）。
- `teachmate.css` 中 23 个变量有 **13 个被重复声明**（所有核心 token 均 2 次）。
- 后果：改一处颜色不一定生效，依赖源码顺序与 `!important` 的隐式博弈。

### 1.3 字号、圆角、阴影、层级极度离散

| 维度 | workbench-app | teachmate | enhancements | 问题 |
|------|---------------|-----------|--------------|------|
| 唯一 font-size | 23 档 | 24 档 | 9 档 | 含 11.5/13.5/14.5 半像素值，无 type scale |
| 唯一 border-radius | 47 种 | 39 种 | 9 种 | 4 套命名：`--shape-*`、`--md-radius-*`、`--tm-radius-*`、`--radius-*` |
| 唯一 box-shadow | 59 种 | 34 种 | 4 种 | 阴影色相包含深紫、亮蓝、纯黑、蓝调、近黑至少 6 种 |
| 唯一 z-index | 13 个 | 8 个 | 2 个 | 无层级 token，值从 -1 到 2000 散落 |
| `!important` | 417 处 | 185 处 | 53 处 | 高 `!important` 密度说明优先级战争严重 |

### 1.4 响应式断点不统一

三个文件共使用 **20+ 个断点值**：1439/1441/1300/1200/1180/1100/1000/900/860/760/720/700/680/640/620/560/480/380 px。同一组件在不同模块下可能提前/延后折行，导致跨页面体验不一致。

## 二、跨模块风格互串（高优先级）

### 2.1 WorkBench 被 TeachMate 品牌色"染色"

- **仪表盘 KPI 卡片**（`desktop-wb-dash.png`）使用了 TeachMate 的便利贴三色系：浅黄 `#fff4c4`、浅薄荷 `#e4f6ef`、浅粉 `#fde0f0`。这与 WorkBench 原本的暖灰紫体系冲突，看起来像把 TeachMate 组件硬塞进 WorkBench。
- **左侧导航 active 态**（所有 WorkBench 截图）使用黄色背景高亮，与 WorkBench 旧体系的深蓝/紫灰 active 态不一致。
- **顶部 Tab 切换器**：WorkBench 模式下 active tab 是深蓝黑（TeachMate 主色），TeachMate 模式下 active tab 也是深蓝黑——TeachMate 的切换逻辑被反照到 WorkBench。

> 项目约束是"仅改 TeachMate，不动 WorkBench shell"，但目前 WorkBench 里已出现大量 TeachMate 视觉元素，需要回清或明确两套皮肤的隔离边界。

### 2.2 WorkBench 背景色自身打架

- 仪表盘、学生管理等页面背景为暖灰米色（`#f4f3f0`）。
- 设置页卡片外背景偏冷灰（`#f7f8fa`）。
- 同一 WorkBench 内切换页面能感觉到"色温"变化。

## 三、组件级视觉问题（按页面）

### 3.1 全局顶部工具栏

- **控件高度/圆角不统一**："+ 新增学生"、"导出 Excel"、搜索框、班级下拉框在同一行但视觉高度不同，圆角从 6px 到 999px 都有。
- **右上角按钮群**："导入数据"深蓝按钮与"导出中心""备份/恢复"白框按钮权重失衡；图标与文字间距松紧不一。

### 3.2 仪表盘（`desktop-wb-dash.png`）

- **KPI 卡片颜色过多**：四个卡片四种背景色，缺少统一的语义映射（例如：人数=中性、均分=中性、及格率=成功绿、优秀率=警告/橙色）。
- **空状态占位弱**："学生层级分布"与"历次考试趋势"两个卡片内只有一行居中小字，大片空白没有图标或引导操作。
- **表格分数高亮**：底部"本次考试前十"中分数统一蓝色，无法区分第一、并列等情境。

### 3.3 学生管理（`desktop-wb-stu.png`）

- **表头与工具栏视觉层级粘连**：表头 `#、姓名、班级、入学英语、家长电话` 与上方工具栏之间缺少明显分隔。
- **操作列"..."按钮**：没有 hover 状态提示，用户不确定是否可点。
- **分页器**："上一页/下一页"深蓝按钮与中间"1 / 4"数字页码风格不统一。

### 3.4 成绩管理（`desktop-wb-score.png`）

- **按钮语义混乱**：同一行出现 7 种按钮样式（深蓝主按钮、白框按钮、红色文字按钮、蓝色文字按钮、禁用态灰按钮、tab 切换、班级 pill）。
- **文字 tab 与 pill tab 混用**："全部汇总/711班/712班"是深色 pill，"成绩表/历次对比/分层分析"是下划线文字 tab，两套交互语言同时出现。
- **排名数字无视觉强调**：班级排名"1"、年级排名"5"没有徽章或颜色变化。

### 3.5 原卷与错题（`desktop-wb-errors.png`）

- **嵌套灰框**："原卷预览"卡片内又套了一层浅灰大框，形成"卡片套灰框套文字"的三层结构，视觉重心被稀释。
- **表头文字色冲突**：错题库表头使用蓝紫色（`#4262ff`？），与 WorkBench 暖灰风格突兀。
- **空状态缺少引导**："试卷资料库"与"错题库"仅文字说明，没有占位插图或"去上传"主按钮。

### 3.6 班级与设置（`desktop-wb-settings.png`）

- **表单标签字号过小**："教师姓名"、"学科"等 label 与输入框内容对比度过低。
- **两个区块按钮重复**："保存设置"与"保存接口配置"都是深蓝主按钮，没有按区块主次区分。
- **说明文字行高不足**："接口地址和 MCP 格式已内置..."段落在卡片内显得拥挤。

### 3.7 日常作业（`desktop-wb-homework.png`）

- **重复空状态卡片**："作业任务"卡片与下方"查看全部记录"卡片均显示"暂无作业任务"，信息重复。
- **"查看全部记录"按钮位置孤立**：卡在两个卡片之间，像悬浮物，没有对齐到列表头部。

### 3.8 待办事项（`desktop-wb-todo.png`）

- **月份标题字号过大**："2026年8月"与其他页面标题字号体系脱节。
- **当前日期蓝框冲突**：29 日的蓝色边框与品牌黄/深蓝紫体系无关。
- **右侧详情卡片**：顶部黄色日期标签与下方"当天还没有安排"的图标风格不统一；"+ 添加待办"深蓝按钮在空状态中过大。
- **日历上月日期灰底过深**：26-31 日灰底与本月白底对比过强，像棋盘。

### 3.9 导出中心弹窗（`desktop-modal-export.png`）

- **四行同色按钮**：四个深蓝主按钮纵向堆叠，视觉单调且没有图标辅助。
- **缺少关闭 hover 反馈**：右上角 X 按钮点击区域小，hover 态不明显。
- **弹窗空间利用率低**：内容仅占弹窗高度 1/3。

## 四、TeachMate 专项问题

### 4.1 欢迎页（`desktop-tm.png`、`mobile-tm.png`）

- **英文副标题字距过宽**："TEACHMATE · AI 教学助手" 字母间距过大，字号又小，显得细碎。
- **输入框发送按钮对比度低**：右下角灰底白箭头在未输入时几乎融入背景。
- **侧边栏用户头像**：黄色圆形内"教"字偏小，像饼干按钮；头像与名字之间缺少留白。
- **"历史对话"空状态**："暂无对话"四字在大量空白中，可加入轻量引导文案或插图。

### 4.2 移动端适配（`mobile-tm.png`、`mobile-wb-dash.png`）

- **顶部 Tab 切换器占空间**：在 390px 宽下，"WorkBench / TeachMate" 仍横向展开，与汉堡菜单、标题挤占 header。
- **TeachMate 欢迎页标题被截断**："你好，我是 TeachMate" 上半部分被遮挡，说明响应式字号未做 `clamp()` 或媒体查询回退。
- **Workbench dashboard 竖排 KPI**：四个 KPI 卡片在移动端占满首屏，用户需滚动很久才能看到趋势图与表格。
- **Header 换行**："初中英语工作台" + 学期切换 + 班级切换在移动端折成多行，高度失控。

## 五、可执行优化清单（按优先级）

### P0：收敛视觉体系
1. **冻结三套 token 合并方案**：建议只保留一套跨 WorkBench + TeachMate 的公共 token（前缀如 `--wb-*`），TeachMate 私有 token 用 `--tm-*` 扩展，禁止 `workbench-app.css` 再引入 `--tm-*` 颜色。
2. **清理 WorkBench 被染色的组件**：仪表盘 KPI 卡片、导航 active 黄色背景、顶部 tab 深蓝黑背景，需要回归 WorkBench 原风格（暖灰紫 + 蓝紫强调）。
3. **统一阴影色**：按记忆约定，全部使用 `rgba(28,28,30, ...)` 近黑阴影，删除 `rgba(5,0,56)`、`rgba(11,18,51)`、`rgba(17,23,53)`、`rgba(25,34,77)` 等蓝调阴影。
4. **合并重复变量声明**：每个 token 只声明一次；如需主题切换用 `body.theme-*` 作用域覆盖，不要在一个文件里重复定义 `:root`。

### P1：组件规范
5. **统一按钮体系**：每个页面最多 3 个层级——Primary（深蓝/近黑）、Secondary（白框灰字）、Tertiary（文字按钮）+ Danger（红色文字/描边）。统一高度 32px/40px、圆角 8px/999px。
6. **统一输入框/下拉**：统一高度 36px、圆角 8px、边框 `#e0e2e8`，focus 环用 `rgba(66,98,255,.22)`。
7. **统一卡片**：统一圆角 12px/16px 二选一，统一阴影 `sm/md/lg` 三档。
8. **统一 type scale**：建议正文 14px、小字 12px、标题 18/20/24px、页面大标题 28px，删除 11.5/13.5/14.5/19/21/22 等中间值。
9. **统一响应式断点**：收敛为 560/860/1200/1440 四档，所有模块共享。
10. **统一 z-index 层级**：定义 `--z-base/10/100/200/300/1000` 等语义层级。

### P2：空状态与微交互
11. **重做空状态**：为图表、列表、资料库增加图标 + 主文案 + 引导按钮（如"去设置分层线"、"上传原卷"）。
12. **增加 hover/focus-visible/active 态**：表格行、操作按钮、关闭按钮、tab 等必须提供反馈。
13. **移动端 header 重构**：小屏下 WorkBench/TeachMate 切换应收进抽屉或 bottom nav；标题与控件垂直堆叠需控制高度。
14. **TeachMate 欢迎页响应式**：标题用 `clamp(1.5rem, 5vw, 2.5rem)`，避免被截断；发送按钮增加 disabled/active 状态对比。

## 七、建议下一步

1. **先冻结**：暂停新增页面样式，避免体系继续扩散。  
2. **做 token 表**：在一份文档（如 `docs/design-tokens.md`）中确定最终 color/shadow/radius/type/z-index 标准。  
3. **从 TeachMate 开始收敛**：按项目约束只改 `teachmate.css`，把阴影、字号、圆角扫到 token 上；同时把 WorkBench 里被误染的组件回退到 WorkBench 原风格（需改 `workbench-app.css`）。  
4. **提取公共组件样式**：把 button/input/card/table/modal/empty 的公共部分抽到 `workbench-enhancements.css` 或一个独立 `workbench-components.css`。  
5. **每改一处 bump `workbench.html` 版本号**，并跑 `tools/audit-responsive.cjs` 验证。
