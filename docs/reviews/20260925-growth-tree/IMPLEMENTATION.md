# 成长树改造落地记录

本文件记录 2026-09-25 复核之后的代码调整。原报告 `CURRENT_IMPLEMENTATION_REVIEW.md` 与原复现 JSON 保留为**修改前证据**；不可将其作为当前仍有缺陷的证明。

**已落地**

1. **撤销与封顶**：在计算奖励前排除已撤销事件，再对有效事件统一分配日/周额度和连续周奖励。撤销账本保留，原事件和撤销事件的当前投影均为0分，避免旧的负分冲正与新额度重新分配相互冲突。新增“第三条原被封顶，撤销第一条后补足额度”和“撤销周目标后中断连周”的回归。
2. **考试成绩更正**：考试自动事件保存来源修订号；分数、出勤、满分、基线等改变时，追加撤销并写入新版本事件；考试或成绩被移除时撤销旧奖励。成绩 API、考试归档/恢复/清除、学校同步与原工作台保存路径均触发对账。显式手工撤销且来源未变时保持撤销；之后真实改分可再次同步。修改历史考试后也会逐场复算后续考试基线。
3. **能力分支**：只使用该考试最新 `confirmed` 试卷版本中被纳入正式分析的题目；同周同分支按有效得分/有效满分汇总，避免草稿、旧版本和题目满分不等造成的失真。
4. **范围与交互**：成长森林和明细请求绑定学期与请求序号，迟到的旧响应被丢弃；切学期清空旧数据；补录和旧版导入在提交中不能重复点击，失败重试复用同一个请求/批次 ID；已打开的旧学期弹窗不能向新学期写入；班级筛选后的顶部统计按该班重算。
5. **读取与画像**：森林、明细和成长摘要的读取路径使用无写入的奖励计算；写入活动时才更新数据库奖励/快照，删去重复重建。画像的成长修订号覆盖活动、能力分支、阶段规则和统计周，摘要传递有证据的分支数值与观察信息；任务事实次数与是否拿到奖励分开。画像引用状态同时校验修订号与规则版本。
6. **规则版本与手工加分**：新增 `growth_term_rules` 学期规则绑定表和迁移；新学期默认 `growth-v4`，迁移从已有快照或奖励推断旧学期规则。新规则对同类型、同满分的最近三次测评取较高基线，避免60→70→60→70反复领取同一段回升。保留原有手工补录，另增教师手工加分1–3点，必填事由、每日一次、每日该类上限3点；已绑定 `growth-v3` 的学期仍只展示和使用原有补录类型。

**边界和后续数据依赖**

- “同类型、同满分”只是当前系统里可落实的保守比较条件，仍不能自动证明两场考试难度相同。更严格的可比组需要学校明确的命题系列/量表标识；在没有该字段前，不宜把进步分当作能力增长的统计证明。
- 教学周、假期、认可请假尚无可信的学期日历数据；当前连续周仍按自然周。不要通过推测学校放假时间自动发奖或延长连续周。需要学期教学日历和请假事实后，再新增规则版本处理。
- 560分的最终阈值、日10/周40的上限仍为试点初值。需要2–4周真实活动机会、补录覆盖和封顶比例数据后调参；不应在既有规则版本上改阈值。
- 读取路径现在无写入，可减少 SQLite 写锁竞争；仍需用真实班级规模测 p50/p95，才能判断是否进一步批量预取和缓存。
- 迁移会绑定已有快照或奖励的学期。没有任何成长事实的旧学期没有可追溯的旧计分规则，将在第一次成长写入时绑定当前默认版本。
