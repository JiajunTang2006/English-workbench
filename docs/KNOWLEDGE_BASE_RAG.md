# 教学知识库与 RAG 方案（v3 · 默认无检索）

状态：v3 设计定稿（2026-08-30）。**P0（编译器）/ P1（服务端 preflight 与分析包）/
P2（单轮路径与工具策略）/ P3（精确深查）/ P4 首批（黄金样例评测 + 观测埋点 +
插件策略预检）已落地并通过全量测试**，实施记录见
`docs/AI_AGENT_DEVELOPMENT_LOG.md` 2026-08-30 条目；剩余：v2/v3 真实模型对比
评测、experience/ 非结构化经验库（按需）。

适用范围：TeachMate 的浙江中考英语考试分析、学生诊断和复习计划。
知识源位于 `backend/app/agent/knowledge/`，当前共 122 个条目、38 个考点 ID。

v3 的核心不是“让模型更快地检索知识”，而是：

> 标准路径不让模型检索。服务端先把数据和知识编译成可执行诊断，只把完成报告
> 必需的短结论、行动建议和 evidence ID 交给模型；只有明确需要原文细节时才升级深查。

## 0. 目标与非目标

### 0.1 目标

1. 标准分析只进行一轮模型生成，不先让模型调用数据包或知识检索工具；
2. 标准场景的知识增量控制在 150~300 token，学生诊断可放宽至 350 token；
3. 系统提示保持静态，最大化跨考试、跨学生的前缀缓存复用；
4. 模型只接收报告所需的 Top 诊断，不接收知识库全文、全量考点表或重复事实；
5. 官方依据、TeachMate 映射和成绩事实均通过 evidence ID 可追溯；
6. 浙江省级笔试与各设区市听力/人机对话版本严格分离。

### 0.2 非目标

- 不把整本课标、命题解析或 122 个条目放进模型上下文；
- 不让模型自由决定“该查什么”；
- 不把向量数据库作为一期依赖；
- 不用条目数量作为启用向量检索的唯一条件；
- 不把知识库改造成长篇百科，条目仍以正确、紧凑、可编译为先；
- **不作用于普通聊天**：未进入三个分析能力的会话（general_chat）不触发
  preflight、不生成分析包、不注入知识增量、不注册深查工具、不登记教学依据
  evidence（详见 5.4）。

## 1. v2 → v3 的关键变化

| 项目 | v2 | v3 |
| --- | --- | --- |
| 数据包获取 | 模型先调用 `get_exam_analysis_bundle` | 服务端在模型启动前内部生成 |
| 标准模型轮次 | 数据工具一轮 + 报告一轮 | 一轮生成并调用 `submit_report` |
| 知识注入 | 首轮工具后组装简报 | 与数据预计算同步完成 |
| 动态内容位置 | 追加到 system prompt | 放入初始分析包，system prompt 完全静态 |
| 模型可见工具 | 成绩分析当前可见 9 个工具 | 标准场景只见 `submit_report`；必要时再见一个升级工具 |
| 知识文本 | 400~600 token 简报 | 150~300 token 诊断行动包 |
| 深查 | 单条全文，最多约 800 字 | 精确短片段，通常 100~250 字 |
| 证据内容 | `data` 与 `facts` 可能同时发给模型 | 完整事实留在服务端，模型只收短事实和 evidence ID |
| 派生卡片 | 可人工编辑并回写 | 全部自动生成，禁止人工直接编辑 |

上述 token 是设计预算，不是供应商账单估算。实现后使用实际 provider tokenizer
或 usage 明细计量，不使用字符数固定换算 token。

## 2. 总体架构

```text
                    构建期（无模型）
Markdown 源条目
  → schema/引用/可信度校验
  → 知识编译器
  → routing.json      题型/考点/错因/课标映射
  → actions.json      短行动建议与适用条件
  → aliases.json      规范 ID 与有限别名
  → source_map.json   条目来源、可信度、内容哈希

                    运行期（模型启动前）
作用域（能力、exam_id、student_id、地区、年份）
  → 服务端内部聚合正式数据
  → 计算 Top 异常/薄弱点
  → 按规则匹配考点、错因候选、置信度和行动建议
  → 登记数据 evidence + 教学依据 evidence
  → 生成 Compact Analysis Packet

                    模型期
静态 system prompt + Compact Analysis Packet
  → 模型一次生成
  → submit_report
  → 服务端校验证据、保存报告、展开来源

                    升级路径（少数场景）
明确需要原文表述/完整任务步骤/附件页码
  → 精确短片段或定向附件读取
  → 最多增加一轮模型调用
```

### 3.2 自动编译目录

建议生成到 `backend/app/agent/knowledge/compiled/`：

```text
compiled/
├── manifest.json      # schema 版本、构建时间、所有源文件哈希
├── routing.json       # question_type → point → error_cause → curriculum_ref
├── actions.json       # action_id、短行动、适用条件、禁用条件、源条目
├── aliases.json       # 受控别名，不做开放模糊匹配
└── source_map.json    # entry_id → 来源、可信度、文件、标题、内容哈希
```

编译产物只由构建脚本生成，禁止人工编辑。源条目变化后，哈希不一致即判定产物过期；
运行时不得静默使用过期产物。

### 3.3 编译与发布校验

编译器可自动强制检查：

- 条目 ID 全库唯一；
- 领域、标签、来源和可信度齐全；
- 考点引用全部能解析到 38 个规范 ID；
- 生成物记录源文件哈希，确保 evidence 可回溯到当时版本。

发布前通过内容审校和黄金测试检查：

- A 级官方条目不得混入 TeachMate 建议；
- C 级映射不得写成官方原话；
- `selected_option` 单独存在时通常不得提升到中高置信度错因；
- 多模态、文化意识、思维品质、学习能力均执行各自证据边界；
- 浙江听力分析必须携带地区和年份，缺失时只使用跨地区通用规则。

## 4. 服务端预计算：标准路径的核心

### 4.1 预计算时机

在创建模型会话之前，由 `run_executor` 或独立的 analysis preflight service 完成：

1. 解析能力和作用域；
2. 内部调用现有数据聚合逻辑，不把 `get_exam_analysis_bundle` 暴露给模型；
3. 计算报告真正需要的指标、Top 异常和薄弱点；
4. 使用 `routing.json` 与置信度函数生成候选诊断；
5. 使用 `actions.json` 选择 3~5 条短行动建议；
6. 将完整事实和完整来源登记到 EvidenceLedger；
7. 只把压缩后的分析包交给模型。

`get_exam_analysis_bundle` 可以保留为内部服务或调试接口，但不再是标准模型工具。

### 4.2 Compact Analysis Packet

建议结构：

```json
{
  "scope": {
    "capability": "exam_analysis",
    "region": "浙江",
    "exam_year": 2025,
    "exam_id": 123
  },
  "metrics": {
    "average": 78.4,
    "pass_rate": 0.86
  },
  "diagnostics": [
    {
      "point_id": "reading.inference",
      "confidence": "low",
      "signal": "推断类题目失分集中；无学生作答过程",
      "action": "要求学生标出原文依据，并用‘证据—结论—范围’复盘",
      "evidence_ids": ["EV-D12", "EV-K07"]
    }
  ],
  "limitations": [
    "仅有得分数据，错因只能作为低置信度候选"
  ]
}
```

约束：

- `metrics` 只保留报告会实际引用的数据；
- `diagnostics` 标准最多 5 条，按影响和可行动性排序；
- 每条只保留一个主要行动，避免模型再次总结长清单；
- 不同时向模型发送表达同一事实的 `data` 和 `facts`；
- 原始题目列表、学生列表和完整来源文本留在服务端；
- 包中仍执行匿名化和最小必要披露。

### 4.3 Token 预算

这里的预算只计算知识规则、诊断行动和局限，不含必要成绩数字：

| 能力 | 标准知识预算 | 深度模式追加 | 标准诊断数 |
| --- | ---: | ---: | ---: |
| 考试分析 | ≤250 token | ≤200 token | 3~5 |
| 学生诊断 | ≤350 token | ≤250 token | 3~5 |
| 复习计划 | ≤300 token | ≤250 token | 3~5 |

超预算时按以下顺序保留：安全/证据边界 → 最高影响诊断 → 对应行动 → 次要诊断 →
背景解释。截断只能丢弃完整条目，不得截成残句。

## 5. 模型可见工具与轮次

### 5.1 能力级白名单

| 能力 | 标准可见工具 | 条件性升级工具 |
| --- | --- | --- |
| 考试分析 | `submit_report` | `get_formal_attachment`（数据包明确缺页码细节时） |
| 学生诊断 | `submit_report` | 精确教学依据短片段（深度模式） |
| 生成复习计划 | `submit_report` | 精确任务步骤短片段（深度模式） |

不要同时向模型暴露全部单项统计工具。服务端可继续内部复用这些函数，但它们不应
占用模型工具 schema token，也不应让模型选择调用顺序。
条件性升级工具只在 preflight 已判定进入深度模式时注册；标准场景不预先暴露。

### 5.2 标准轮次

标准路径：

```text
服务端 preflight → 模型生成 submit_report 工具调用 → 工具成功 → 结束
```

`submit_report` 成功后不再要求模型补一段重复的自然语言总结。前端直接渲染已保存的
结构化报告。只有附件升级、证据不足或输出校验失败时才允许额外模型轮次。

### 5.3 Prompt 去重

- system prompt 只保留角色、安全、证据纪律和输出原则；
- 完整输出 JSON schema 由 `submit_report` 工具定义，不在 prompt 中重复；
- 不在 system prompt 中追加考试专属知识或动态简报；
- 同一规则只保留一份，优先由服务端校验而不是让 prompt 反复提醒。

### 5.4 普通聊天边界（硬约束）

**未进入三个分析能力的会话（general_chat）不启用本方案任何环节。** 三道门：

1. preflight / 分析包只由三个分析能力的 run 触发；general_chat 不执行
   数据聚合、不生成 Compact Analysis Packet、无知识增量 token；
2. `submit_report` 与升级工具不注册到 general_chat 的工具白名单
   （general_chat 保持 `required_tools=[]`、`requires_evidence=False`）；
3. general_chat 不登记数据 evidence 和教学依据 evidence。

边界判定：

- **分析会话内的追问**（run 已绑定作用域）属于"正在使用插件"，
  分析包继续生效，属正常路径；
- **未绑定分析能力的聊天**为裸聊天：AI 用自身通用知识直接回答，
  不读知识库、不读成绩数据、不留知识库引用痕迹；
- 知识库定位是"分析依据"，不是聊天语料；教师裸聊天问教学问题
  （如"宾语从句怎么教"）时按通用知识回答，与普通 AI 助手一致。

验收项：普通聊天 run 的 payload 中不得出现教学依据 evidence、分析包字段或
升级工具 schema（并入 10.2 验收标准）。


## 6. Evidence 设计

### 6.1 两类 evidence

1. **数据 evidence**：成绩、分布、题目统计、学生趋势、正式附件；
2. **教学依据 evidence**：课标条目、浙江命题事实、TeachMate C 级映射与行动规则。

每个诊断至少包含一个数据 evidence；使用课标语言或教学建议时，再附对应教学依据
evidence。模型只看到 compact claim 和 evidence ID，服务端保存：

- 完整事实；
- entry ID 与可信度；
- 源文件及内容哈希；
- 适用的地区、年份、题型和考点；
- 生成该候选的规则版本。

报告展示来源时由服务端解析 ID，不让模型重复抄写长来源名称。

### 6.2 证据纪律

- 只有 score/correct：错因最高为 low；
- 只有 selected_option：通常仍为 low；
- 有 student_answer_text：可缩小候选，不能还原完整思维过程；
- 有清晰过程记录或教师确认：才可提高置信度；
- 文化意识、学习能力、情绪因素和语音听辨均不得由单次得分直接判定；
- 2025 主题和题号仅是当年事实，不用于预测下一年。

## 7. 深查与真正的 RAG

### 7.1 核心知识：精确升级，不做向量召回

122 个结构化核心条目使用：

```text
规范 ID 精确匹配 > 受控别名匹配 > 明确失败
```

升级只返回完成当前结论所需的短片段，通常 100~250 字，并附 entry ID、可信度和
evidence ID。默认不返回整条全文，更不返回相邻无关条目。

以下场景允许升级：

- 用户明确要求课标原文口径；
- 报告需要某个复习任务的完整步骤；
- 正式附件数据包明确缺少某个页码细节；
- 输出校验指出某结论缺少可解析依据。

以下场景不得升级：

- 只是为了让报告显得更详细；
- 标准分析包已经给出可执行行动；
- 试图用知识文本弥补缺失的学生作答证据；
- 试图预测下一年度中考。

### 7.2 非结构化经验库：先 FTS5，后向量

未来 `experience/`、课堂案例和开放问答材料增多时，可建立独立的本地离线索引：

- SQLite FTS5/BM25；
- 中文 2/3 字 n-gram；
- 受控同义词；
- source/type/region/year 过滤；
- 去重和邻接片段；
- 返回源路径与条目 ID。

该索引与核心规则库分开，不能让经验材料覆盖 A 级课标或官方命题事实。

向量检索只在有标注查询集的离线评测证明 FTS5 持续漏召回，且通过别名/同义词无法
修复时考虑。评测至少记录 top-1、hit@3、MRR 和错误类型；不得仅因条目超过某个数量
就引入 embedding。

## 8. 缓存策略

1. **静态前缀缓存**：system prompt 和能力级工具 schema 不包含 exam_id、student_id
   或动态知识；
2. **编译缓存**：按源文件哈希复用 compiled 产物；
3. **分析包缓存**：按 capability + scope + 数据版本 + 规则版本 + 知识哈希缓存；
4. **证据缓存**：缓存只复用事实快照，不跨数据版本沿用旧结论；
5. **失败策略**：知识编译产物过期或证据登记失败时，正式分析应 fail closed，不使用
   无来源的内存结论。

## 9. 三个能力的运行映射

### 9.1 考试分析

- 服务端聚合总体数据、分布、Top 异常题、薄弱考点和必要风险摘要；
- 依据题型和实际数据选择 3~5 个诊断；
- 只有具体文化任务才使用 cultural_awareness；
- 任务型阅读只有含非文字资源时才使用 reading.multimodal；
- 浙江听力按地区和年份路由，缺地区时只给跨地区通用诊断。

### 9.2 学生诊断

- 使用该生错题、答案文本、趋势和教师确认记录；
- 数据不足时只生成候选，不强行填满素养四维；
- 不因成绩波动直接推断焦虑、态度、时间管理或学习能力；
- 每个行动必须对应一个可验证的下一步任务。

### 9.3 复习计划

- 服务端从已确认或有证据的薄弱点选择任务 A~E；
- 默认门槛属于 C 级观察规则，不写成课标规定；
- 计划只安排 3~5 个优先目标，避免把全部考点装进上下文；
- 听力/人机对话按当地方案加入，不能从省级笔试结构推断。

## 10. 观测指标与验收标准

### 10.1 必须记录

- 每次 run 的模型输入/输出 token；
- system prompt、工具 schema、分析数据、知识增量分别占用多少 token；
- 模型调用轮数；
- 模型可见工具数；
- 深查调用率、命中率和返回字符数；
- 分析包截断次数；
- evidence 解析失败次数；
- 知识编译过期或失败次数。

### 10.2 v3 验收标准

1. 标准考试分析不出现 `get_exam_analysis_bundle` 模型工具调用；
2. 标准路径一轮模型调用后完成 `submit_report`；
3. 每个能力标准可见工具不超过 2 个；
4. 标准知识增量满足第 4.3 节预算；
5. 模型 payload 不同时包含重复的完整 `data` 与 `facts`；
6. 所有 finding/recommendation 的 evidence ID 均可解析；
7. 修改源条目后，旧 compiled 产物必定被检测为过期；
8. 122 条源知识、38 个考点无重复 ID、缺失字段或失效引用；
9. 缺少学生作答过程时，自动化测试不允许输出高置信度错因；
10. 缺少地区/年份时，听力不得套用具体地市题型或评分规则；
11. general_chat 会话的 payload 不含分析包字段、教学依据 evidence 和升级工具
    schema，自动化测试覆盖该边界。

## 11. 分阶段实施清单

### P0：知识编译器与校验

- 新建 `knowledge/compiled/` 生成流程；
- 生成 manifest/routing/actions/aliases/source_map；
- 加唯一 ID、字段、引用、哈希和地区听力边界测试；
- CI/构建时拒绝过期产物。

### P1：服务端 preflight

- 把现有 `_tool_exam_analysis_bundle` 聚合逻辑下沉为可内部调用的 service；
- 在模型会话创建前生成数据 evidence、教学依据 evidence 和分析包；
- 对学生诊断、复习计划建立对应内部 bundle；
- 模型 payload 去除重复 `facts` 和不必要的全量列表。

### P2：工具与 Prompt 精简

- 成绩分析移除模型可见的 bundle/单项统计工具；
- 按能力动态注册 `submit_report` 和必要升级工具；
- prompt 删除重复 JSON schema 和动态知识注入逻辑；
- `submit_report` 成功后立即结束标准 run。

### P3：精确深查

- 实现按 entry ID/受控别名返回 100~250 字短片段；
- 只在深度模式或明确缺证据时暴露；
- 深查结果登记教学依据 evidence；
- 加默认不调用、一次上限和预算测试。

### P4：评测与调优

- 建立浙江中考黄金样例：考试分析、学生诊断、复习计划、听力地区边界；
- 对比 v2/v3 的模型轮数、输入 token、报告证据完整率和建议可执行性；
- 达到验收标准后再删除 v2 动态简报路径；
- 只有非结构化经验库评测证明需要时，才评估 FTS5 或向量方案。

## 12. 最终决策

TeachMate 的核心知识库不是“给模型搜索的文档集合”，而是：

> 人工可审、机器可编译、运行时可计算、证据可追溯的教学规则源。

因此默认路径采用 **Knowledge Compiler + Deterministic Guidance Packet**，不采用传统
向量 RAG。RAG 仅保留给非结构化经验材料和少数原文深查场景。
