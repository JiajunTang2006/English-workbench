## 发现的问题

### 1. [已修复，原 P1] 恢复考试或出勤状态后，成长积分不会恢复

- 位置：`backend/app/services/growth/exam_events.py:155-157`。
- 范围：本地与 GitHub 均有，文件内容相同。
- 触发：已有正常成绩，先归档考试再恢复；或者把出勤改成缺考，再改回出勤且保留原成绩。
- 临时数据库实测：初始积分 `2` → 归档/缺考后 `0` → 恢复后仍为 `0`；恢复同步返回 `created=0, skipped=1`。
- 原因：`last.source_revision == revision` 时直接跳过，没有区分上一次事件是被教师主动撤销，还是被系统因归档/缺考自动撤销。原分数恢复后指纹相同，因此始终被当成重复来源。
- 修复：区分系统自动撤销和教师手动撤销。系统撤销的来源重新有效时重新记账；教师明确撤销的记录保持撤销。回归覆盖考试归档恢复、缺考恢复和教师手动撤销。

### 2. [已修复，原 P2] 学生快照缺少性别字段时，会清空现有性别

- 位置：`tools/import_student_snapshot.py:78-83,96-101`。
- 范围：仅本地新版；GitHub 版本没有这段性别写入逻辑。
- 触发：对已有性别的学生导入仅含学号、姓名、入学成绩的合法快照，并使用 `--apply`。
- 临时数据库完整流程实测：原性别为 `女`，成绩无需修改，导入仍报告 `gender_changes=1`，导入后性别变成 `None`。默认备份流程正常生成了备份，但不能避免错误写入本身。
- 原因：`row.get("gender")` 把字段缺失当成清空指令，并直接写回数据库。脚本说明还声称只更新入学英语成绩。
- 修复：只有快照中明确包含 `gender` 字段时才更新性别。字段缺失会保留原值；显式 `null` 仍可清空。回归覆盖缺字段、更新值及显式清空。

### 3. [已修复，原 P2] 浏览器回归测试的迁移版本断言已过期

- 位置：`tests/e2e/baseline.spec.js:39`。
- 范围：本地；GitHub 未上传该测试文件。
- 实测：桌面、窄屏两个项目均失败。测试期望 `20260901_0027`，接口实际返回 `20260926_0030`，后者与 `backend/app/version.py` 及当前迁移版本一致。
- 影响：现有端到端检查及依赖它的发布检查无法全绿，掩盖真正的回归信号；这不是运行时接口失败。
- 修复：端到端测试从 `backend/app/version.py` 读取 `SCHEMA_REVISION`，再与运行时接口比较；版本缺失时明确失败。桌面和窄屏两组版本检查已通过。
