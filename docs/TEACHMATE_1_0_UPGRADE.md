# TeachMate 1.0 改造说明

日期：2026-09-30。当前源码版本：1.0.0；数据库迁移：20260930_0033。按用户要求，本轮不生成安装包，不更新已安装应用，不发布 Release。

## 本轮交付

本轮完成教师端的一条连续工作流：教学目标 → 核对诊断 → 准备材料 → 课堂实施记录 → 复测与反馈 → 调整下一次教学。教学任务独立于聊天会话保存，换对话或重启后仍可继续。

| 环节 | 已实现的行为 | 教学意义 |
| --- | --- | --- |
| 确定目标 | 创建任务；固定学期、学科、班级和考试；填写课时、教材、已教内容、活动偏好及是否增加作业 | 生成内容受实际教学条件约束 |
| 核对诊断 | 从已完成报告创建任务；任务范围来自原报告；逐条记录对 AI 判断的修正原因 | 教师可以纠正“未教过”“题目有歧义”等解释 |
| 准备材料 | 采用报告后保存课堂流程、学生练习、教师答案和后续测评；也可手工添加 | 将分析建议转成可用材料 |
| 修订材料 | 单份编辑、历史版本查看与恢复；过期版本保存时提示冲突 | 教师修改保留，不被后续操作静默覆盖 |
| 使用材料 | 单份预览与打印，可通过系统打印保存 PDF；学生练习与教师答案分别操作 | 学生打印件不混入其他教师材料 |
| 收集反馈 | 课堂观察、实施记录、AI 判断修正、单条或 CSV/Excel 复测导入 | 反馈成为下一轮备课上下文 |
| 复盘 | 分别汇总答对次数和独立新题表现，同一学生/目标/日期采用最新修正，原记录保留 | 当次答对、活动参与与稳定掌握保持区分 |
| 继续与归档 | 同任务可以有多个对话；完成或归档后停止内容写入，重新打开后继续 | 保留可追溯的教学过程 |

个体诊断仍保存在学生对话中，当前教学任务面向班级及一般备课，不将个体诊断直接采用为全班材料。采用报告不等于确认正式学情结论，也不写入成绩或掌握状态。

## 使用方法

1. 在 TeachMate 首页点“新建教学任务”，写清学生应学会什么及课堂条件；也可以在分析报告下方点“围绕本报告创建教学任务”。
2. 在任务工作区选择“核对诊断”或“准备教学”。按钮将要求填入对话框，教师可修改后发送；模型调用仍使用原有配置、范围校验和预算确认。
3. 查看生成的报告，明确点击“采用本轮报告”。采用后的材料保存在任务中；同一任务重复采用同一报告不会重复添加材料。
4. 单份材料可手工编辑、请 AI 修改、查看版本或打印。“请 AI 修改”选定这份材料作为上下文焦点；“结束本次材料修改”退出焦点。
5. 上课后记录课堂反馈，或录入复测。复测字段包括学生、学习目标、日期、是否答对、是否独立完成、是否使用新题。
6. 切到“反馈复盘”，点“根据反馈调整教学”，继续对话。任务阶段由教师操作，AI 不自行声称已实施或已保存材料。

复测 CSV/Excel 表头：学号、目标、正确、独立完成、新题、日期、备注。前三个布尔列用 1/0 或 是/否；日期采用 YYYY-MM-DD。CSV 使用 UTF-8。每批最多 500 行、文件最多 2 MB；不匹配任务班级的学号会拒绝导入，不进行部分写入。当前没有从纸面作答自动识别复测成绩的流程。

## Token 使用方式

新增的教学任务状态在本地生成，最多使用保守估算的 **3500 Token**；这是任务上下文的上限，不是整个模型请求的上限。保留目标、课堂条件、近期反馈和复测汇总，材料只发送节选。超过预算时删除完整的可选条目，保持 JSON 完整，并明确说明内容只是节选。

修改某份材料时优先发送该材料，其他完整材料留在本地。按钮不再把整份正文和全部条目再次复制进用户输入。任务上下文在运行创建时冻结，后续教师修改应用于下一轮；费用预估计入这部分上下文。历史消息仍使用原有摘要和预算机制，不新增总结用的模型调用。

节选意味着模型可能看不到材料的全部细节，教师仍需核对完整题目和答案。未使用真实 Provider 对同一任务进行前后对比，**不宣称已经节省某个百分比 Token，也不宣称改善了真实学习效果**。

## 同类项目参考与适配

[DeepTutor 官方仓库](https://github.com/HKUDS/DeepTutor) 将辅导、练习和掌握检查组织在持续的学习工作区；本轮借鉴持续状态与反馈循环，把它适配为教师可核对、可修订的教学任务，而不是引入完整的学生互动系统。

[OpenMAIC 官方仓库](https://github.com/THU-MAIC/OpenMAIC) 提供生成课程、编辑教学内容和交互课堂；本轮借鉴教学成果可编辑的思路，在现有本地工作台中实现材料编辑与版本恢复，没有移植其运行框架或源码。

## 验证与边界

新增后端测试覆盖任务与多对话持久化、版本冲突与恢复、作用域校验、复测整批拒绝、教师修正、运行上下文冻结、重复报告采用、上下文预算和报告创建原子性。迁移测试从上一版数据库升级，检查已有聊天及结构化报告仍然保留。

浏览器测试覆盖任务创建、修改、恢复、课堂反馈、重载后继续、新对话继续、学生打印件不带入教师答案、完成后重新打开、复测导入与错误名单拒绝。桌面与较窄桌面均验证；另检查 780 像素宽度时上下排列。

正式数据目录未用于测试，未调用真实付费模型。已有聊天和报告展示继续使用原有路径；新迁移在测试数据库上验证，不代表已安装应用已迁移。

后续优先完成[教师对话核心改造](TEACHMATE_CONVERSATION_CORE_PLAN.md)：统一本轮范围与身份映射、改善自然对话和多轮指代、允许 AI 按需取证、完善第三方模型适配，并建立准确性与 Token/时延评测。姓名问题作为核心验收场景，不单独用关键词补丁处理。该方案已完成调研，功能仍待实施，不计入上表已交付内容。

用户已确认将个人专项弱项练习、分层练习、教案协作与连续修改、作答反馈、新题复测、跨阶段表现评估、学生逐步提示与互动练习全部纳入后续开发。实施顺序、依赖和验收见[后续开发任务总表](TEACHMATE_NEXT_DEVELOPMENT_TASKS.md)，优先修复教师对话核心；材料质量检查、Token/时延评测与使用反馈贯穿各阶段。这些新增任务不计入本轮已交付范围。
