# 成长森林补录与弹窗修复

## 问题及处理

旧版教师补录与自动奖励共用类别次数、每日总分（10）和每周总分（40）上限。记录保存成功后可能实际入账为 0，但界面只提示“已记录”，造成录入失败的误解。

根据用户明确选择，新教师补录使用 `teacher_confirmed_v1` 事件策略：所有允许的手工类别按教师确认的正整数分值完整入账，不受上述上限限制，也不占自动奖励额度。快捷按钮使用所示分值，自定义及批量表单可调整分值。成功提示显示服务端实际入账总分。原有重复请求保护、学期范围检查及追加撤销事件机制保留。

新策略在事件载荷中标记，未标记的历史事件仍按原规则计算，不自动补发历史零分记录。确认需要重新计入的历史误录，可撤销后按实际事由重新录入；不应重复保留两条相同有效活动。自动考试奖励规则保持原样。

成长明细弹窗最大宽度调整为 1200px，并随视口收缩；窄窗口改为单列。日期与操作避免断字，封顶原因允许自然换行，事由单独占据较宽列。重新打开时清除旧滚动位置，标题固定、正文滚动。其他弹窗重新打开时恢复标准尺寸。

## 使用

后端没有热重载，需关闭并重新启动本地工作台，再刷新浏览器页面，才会使用新的计分逻辑。前端资源版本标记已更新。本次仅修改本地项目，没有推送 GitHub。
