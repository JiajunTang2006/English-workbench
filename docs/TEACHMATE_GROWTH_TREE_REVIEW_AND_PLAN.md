## 2. 产品结构：同一棵树表达三类信息

| 元素 | 表达什么 | 计算来源 | 边界 |
| --- | --- | --- | --- |
| 树干与成长阶段 | 本学期已完成且可核对的学习活动积累 | 成长事件与规则 | 不是英语能力等级，也不是学生排名 |
| 能力分支 | 词汇、语法、阅读、听力、写作的近期测评表现 | 对应小分、明确技能映射和评分量表 | 无证据的分支显示“待记录”，不能用总分拆分或补零 |
| 近期状态 | 最近一段时间的完成、订正、可比表现变化 | 有日期的任务与测评记录 | 数据不足时明确显示，不自动判定退步 |

后续有可靠口语量表时再增加口语分支。默写只能支撑对应词汇/拼写表现，不能自动支撑阅读、听力能力；“课堂主动回答”属于观察记录，不能直接作为语言能力正确率。

森林首页建议保留树卡片，但主信息改为“阶段、本周新增、下一步小目标、记录覆盖情况”。点击学生显示来源明细、五个分支、待订正任务和历史年轮。默认按学号或姓名展示；成长值排序作为教师可选视图。班级汇总优先显示本周参与人数、任务完成率、订正完成数，总营养作为补充。

班级展示/导出提供展示模式：用别名或学号，隐藏扣分原因、需关注事项和画像全文。教师自己的管理界面仍可查看完整记录。

## 3. 第一版计分规则

以下数值是可上线试点的产品初值，不是从现有学生数据训练出来的最优参数；先模拟历史活动频率，再冻结一个学期的规则版本。

### 3.1 以事件记账

| 事件 | 建议奖励 | 约束 |
| --- | --- | --- |
| 完成一项已布置学习任务 | +2 | 每天最多两项计此类奖励；仅创建任务或导入空记录不算完成 |
| 完成订正并被确认 | +2 | 同任务只奖励一次，每天此类最多 +2；原题无误者可完成等量巩固任务获得同类机会 |
| 完成计划内的间隔复习/达标复测 | +3 | 每个计划复习节点一次，每天此类最多 +3；同日反复重做不重复奖励 |
| 教师确认的具体课堂/阅读表现 | +1 或 +2 | 必须有事由，手工类每天最多 +2；同任务已自动奖励的完成行为不得手工再奖 |
| 达成个人周目标 | +2 | 每周最多一次，目标事先设定、有可核对证据；属于里程碑奖励 |

所有类别合计每天最多 **8 点**，每个自然周最多 **30 点**。一次活动允许“完成”和之后的“验证订正/间隔复习”分别奖励，因为对应不同学习行为；同一行为的自动记录、补录、重传则必须合并为一条事实。预算上限只限制营养，不能删掉原始学习证据。

给定事件拟奖励值 `r`，先验证有效性和幂等，再取：

```text
本次实际奖励 = min(r, 当日该类别剩余额度, 当日总剩余额度, 当周总剩余额度)
学期营养 = max(0, 本学期有效奖励合计 + 误录更正的净调整)
```

存储整数点数；保留“原本可得、实际入账、封顶原因”。补录的发生日期与录入时间分开保存，额度按发生日期和学校时区计算。补录或改分影响封顶分配时，按稳定的发生时间与事件 ID 顺序重算受影响日期/周，记录调整差额。

考试原始分数进入学业表现分支。确认实际参加考试后，可按任务完成记基础奖励；不再因为高起点而自动获得数倍营养。高水平学生通过保持性复习、迁移任务也有成长机会。成绩下降不扣已有营养，另在教师视图提示需要支持的部分。

### 3.2 缺失、缺考与扣分

- `missing`：尚未录入，不奖励、不扣分、不计为学业零分。
- `absent/excused`：缺考/请假不奖励考试完成，也不生成能力零分；任务覆盖率按“应完成”和“免除”分别统计。
- 有效 0 分：是真实测评结果，可以进入对应学业统计；若确实完成任务，仍可得到基础完成奖励。
- 作业未交/未订正：产生待办与后续干预，不从已完成活动中扣回营养；补做后关闭待办并按规则入账。
- 误录奖励：生成一次性撤销/更正事件，引用原事件，禁止删除原记录或反复撤销。若更正导致阶段变化，明确显示“记录已更正”，不悄悄改变历史。
- 如果学校必须保留纪律积分，独立展示，不能改写学业分支或混入成长总值。

### 3.3 阶段和视觉进度

建议试点阶段阈值为 **0、20、60、120、200、300、420**，沿用种子、发芽、小树苗、茁壮成长、开花、结果、森林之星七种视觉。假设普通参与每周获得约 24 点，首次发芽约一周，最后阶段约 17.5 周；这是节奏推演，不是当前班级的真实统计。达到周上限时最早约 14 周完成。

上线前用实际学期周数、任务频率和入班时间校准，避免“全班长期种子”或“两周全部满级”。阈值调整在新规则版本生效，既有记录仍可按旧规则复算。中途转入学生不补造活动，可展示入班后的完成率和个人目标。

```text
阶段内进度 = (当前营养 - 当前阶段起点) / (下一阶段起点 - 当前阶段起点)
```

到最高阶段后显示“本学期继续积累”，下学期增加年轮并开启新学期树。历史阶段与新学期营养分别展示，不让老生因为历史总量永远压过新生。

## 4. 能力表现与模型选择

### 4.1 为什么不先 Softmax 再线性回归

Softmax 输出互斥类别的概率，例如属于 A/B/C 类的概率；它不定义“多少营养合理”。如果先用现有分数阈值生成类别标签，再训练分类器，模型主要是在复现规则；之后分组回归又增加误差传递和小样本不稳定。如果分类表示“词汇薄弱、阅读薄弱”，这些状态可以同时存在，也不适合用互斥 Softmax。相关能力定义可参见 [scikit-learn LogisticRegression 文档](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)。

`0.4×完成度+0.3×正确率+0.3×进步幅度` 这类人工设权是加权规则，不是已经训练好的线性回归。回归必须先有独立、明确的目标值，例如下一次可比测评的分数，才能用数据拟合系数。

| 要解决的任务 | 建议方法 | 使用条件 |
| --- | --- | --- |
| 营养与树阶段 | 确定性事件规则＋阈值映射 | 第一版直接采用，不需要训练标签 |
| 分项近期表现 | 可比测评得分率＋指数平滑，保留原始记录 | 题目/任务有明确分项、满分和日期 |
| 简短成长说明 | 确定性模板 | 页面打开、积分变化时即可本地生成 |
| 教学建议和连贯画像 | 现有文本模型读取结构化证据 | 不让模型计算积分或修改源记录 |
| 预测下一次可比测评成绩 | Ridge 回归作为候选基线 | 有跨时间标签和留出验证；目标是预测而非奖励 |
| 预测需要哪类支持 | 有序模型或多标签分类，按目标选择 | 有教师定义的独立标签、误报成本及验证集 |
| 跟踪具体知识点掌握 | BKT 等知识追踪模型 | 有题目—知识点映射和时间有序作答，验证后再加入 |

Ridge 对系数使用 L2 正则，可作为小型表格预测任务的基线，但不保证在本项目上有效；要与“最近一次成绩”“最近几次均值”比较。[Ridge 官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)。BKT 面向按时间排列的作答与知识掌握，不适合直接解释奖励积分；见作者维护的 [pyBKT](https://github.com/CAHLR/pyBKT)。

### 4.2 第一版的分项表现算法

对同一能力、同一可比测评组，计算 `x=有效得分/满分`。可比组至少包含评分量表版本、任务类型、年级/教学阶段和题目范围；仅除以满分并不能消除试卷难度差异。无法建立可比关系时分开显示，不输出统一“能力提高了多少”。不同考试中的标准分/百分位只能表示相对位置，另列显示，不能自动解释为绝对能力增长。

可先将同周同组的有效测评合成一个观察值，避免重复练习次数支配趋势，再使用：

```text
M₁ = x₁
Mₜ = 0.3 × xₜ + 0.7 × Mₜ₋₁
```

0.3 是待试点调整的平滑系数。没有新记录就不更新，不把缺失填成 0，也不因为放假自动衰减能力值。指数平滑的基本定义可参见 [NIST EWMA](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm)；本方案只采用平滑形式，不把工业控制图阈值当教育诊断标准。

分支必须同时展示观察次数、时间跨度、最近日期和量表来源。第一版建议少于三个不同日期的可比测评时只显示记录与“样本较少”，不标稳定提升。趋势比较使用两个不重叠窗口，各至少三个可比观察；可先将 ±5 个百分点作为展示候选阈值，并要求连续两次更新方向一致。它是产品提示规则，不是统计显著性判断，需用试点数据调校。

低置信 OCR 结果先作为待核对资料，不进入确定的营养或学业表现；总分与小分不一致时分别保留来源，标明差异，不自动按比例摊到各能力分支。

### 4.3 后期真的需要训练模型时

先明确目标，如“预测下次同量表阅读测评得分”，再准备训练数据。不能用人工营养总值当唯一标签声称模型学会了真实成长，也不能以模型自己生成的画像为掌握能力的真值。

验证区分两种场景：预测已知学生的未来表现采用时间向前切分；泛化到新学生还需按学生/班级留出。训练特征只取预测时点之前的信息，不能把之后的订正、画像或考试结果泄漏进去。误差、校准、分组表现和教师可解释性都满足要求后再上线，而不是积攒到任意一个样本数就启用。相关切分原则见 [scikit-learn 交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)。

目前不需要为成长树单独换一个大模型。继续复用现有文本模型做教学解释，视觉模型只负责资料识别；用固定脱敏样例比较证据忠实度、遗漏率、耗时与成本后再决定具体供应商。

## 5. 工程方案：模块化单体与独立事实服务

继续沿用本地 FastAPI＋SQLite，新增独立成长模块。当前单教师桌面产品没有必要先拆微服务或引入复杂消息集群。关键是统一事实来源、增量计算、可重放和模型权限边界。

```mermaid
flowchart LR
    A[考试小分 / 学习任务 / 教师观察] --> B[统一校验与稳定身份映射]
    B --> C[学习事件账本]
    C --> D[成长规则服务]
    C --> E[分项表现服务]
    D --> F[成长快照与本地接口]
    E --> F
    F --> G[Workbench 森林与学生详情]
    F --> H[TeachMate 分析包及证据]
    H --> I[画像摘要与教学建议]
    I --> J[有来源和版本的画像修订]
```

### 5.1 建议数据结构

| 数据对象 | 必要字段与职责 |
| --- | --- |
| 学习任务/来源适配 | 稳定 `task_id`、所属学期与学生、发生时间、分项、量表、满分、完成状态；当前默写数组下标不能作为长期 ID |
| `growth_events` | `id, student_id, term_id, class_id_at_event, source_type, source_id, source_revision, event_type, occurred_at, recorded_at, business_date, payload, actor, reverses_event_id`；记录发生了什么 |
| `growth_awards` | `event_id, rule_version, proposed_points, applied_points, cap_reason, calculation_revision`；记录为什么给这些点 |
| `growth_rule_versions` | 不可变参数、阶段阈值、时区、启用学期和生效日期；教师修改产生新版本 |
| `student_growth_snapshots` | 学期积分、阶段、周摘要、分项观察值、样本量、源版本指纹、规则版本、计算时间；是可重建缓存，不是第二套事实 |

身份统一用数据库 `Student.id`；参考前端的 `state.students[].id` 实际常是学号，不能直接作为数据库主键使用。迁移时通过学期 Enrollment 和 student_no 映射；重号或无法映射的数据进入人工核对清单，不能按姓名猜。

对来源修订执行唯一约束；重试同一请求不得新增积分。原记录更改时保存新事件版本及调整，旧事件保留审计。一个活动同时来自自动同步和教师补录时，按规范化来源键合并。若来源无法确认，先标记待核对，不因为已有总值就再发一份奖励。

新数据写入和待重算标记在同一数据库事务提交；可以用轻量 outbox/待处理表，后台按学生学期串行归并。普通写入只重算受影响的学生及周窗口，不在每次页面渲染时遍历全班所有历史考试。批量操作共用 batch_id，提交前验证当前范围；学期切换后旧请求返回不得污染新页面。

## 6. 成长树怎样进入画像

**动态成长事实与 AI 叙述分开保存。** 积分、阶段、活动覆盖率和来源是后端确定性输出；画像中的解释、建议是模型输出，必须引用前者。成长事实变化可即时更新卡片，无需每加一次分都重跑完整画像。

建议新增 `growth_summary`：

```json
{
  "schema_version": "1.0",
  "rule_version": "growth-v2",
  "term_points": 86,
  "stage": "小树苗",
  "week_points": 24,
  "observed_task_completion": {"completed": 9, "eligible": 10},
  "verified_corrections": 3,
  "dimensions": {
    "reading": {"status": "insufficient_comparable_history"},
    "listening": {"status": "no_evidence"}
  },
  "source_revision": "example-revision",
  "evidence_refs": ["growth-event:example-1"],
  "limitations": ["阅读可比测评不足，暂不判断稳定提升"]
}
```

以上为合成示例。对应画像可写：“本周已记录任务完成 9/10，完成 3 次经确认的订正，学习活动较持续。阅读的可比测评记录尚不足，暂不能判断稳定提升；听力资料暂缺。下一阶段建议安排一次同量表阅读复测。”不应写“营养 86，说明英语能力优秀”或从扣分备注推断人格、自律程度。

接入现有画像修订机制时：

1. 在生成分析包时冻结成长快照与证据 ID，限制到当前学生和学期，复用匿名化处理。
2. 后端维护数值字段；模型只生成叙述和建议，不能改积分、置信状态或教师原话。
3. 沿用现有自动画像流程时，新增成长叙述明确标记模型来源，保留版本和教师改写；缺证据的判断不自动进入正式结论。
4. 事实更正后相关画像标为“依据已更新”，定时聚合或下次诊断时刷新，不在每次小事件后同步调用模型。
5. 画像解释本身不作为下一次成长奖励的证据，避免“模型说进步→加分→模型又以加分认定进步”的循环。
6. 跨学期只继承带时间范围的历史摘要和年轮；新学期活动、分母、营养重新累计。

## 7. 旧版迁移策略

不覆盖 Windows 包内文件，也不通过新公式静默重算已展示过的所有历史奖励。

- 先导入预览：学生映射、学期、手工记录数、旧计算总分、异常空分/缺考奖励、负值、重复候选和无法识别来源。
- 旧考试/默写活动若有稳定 ID 和日期，可映射为历史事件；缺日期的数组只保留为旧版累计依据，不擅自分配到某一天或声称形成连续学习记录。
- 手工旧记录只有日期、分值、备注，按“迁移批次＋原学期＋学号＋原位置”生成稳定迁移键，保留原值与原文；不能把两条完全相同记录自动判成同一事件。
- 旧总值保留在“历史营养（旧规则）”；纠正空分等奖励须出具差异清单。若选择学期中启用新规则，采用教师确认的切换日和期初结转值，避免同一历史事件同时在结转与新规则中计奖。
- 导入幂等、可整批撤销；迁移前做本地备份，备份/恢复包含成长表与规则版本。回滚以逆向迁移记录/恢复一致数据为准，不只删除新前端文件。

## 8. 实施顺序和验收

| 阶段 | 交付 | 必须通过的验收 |
| --- | --- | --- |
| 0：修正事实链 | 小分合并与不完整批次保护、统一正式试卷口径、完整分析指纹、统一 PDF 渲染 | 部分补读失败不清空原分；草稿状态一致；标签变化能使旧报告过期；干净 Windows 可解析扫描 PDF |
| 1：成长树最小可用版 | 事件账本、规则版本、成长快照、森林页、单人明细、补录和撤销 | 空分/缺考不误奖；重复提交不重复计分；学期隔离；每一点可追溯；范围切换清理批量选择 |
| 2：画像接入 | 成长事实卡、证据摘要、模型叙述与修订 | 模型关掉仍可用森林；无小分不生成五项能力；数值与事件明细一致；更正后画像标过期 |
| 3：试点校准 | 真实教学周期的节奏、覆盖率和教师负担评估 | 不同起点学生都有有效成长路径；积分无异常刷高；分支不以缺失当零；规则变更可回放 |
| 4：可选预测 | Ridge/BKT/分类候选与独立验证 | 优于朴素基线、无时间泄漏、误报可接受、版本可回退；不达标继续使用规则与描述统计 |

建议性能验收初值：指定一台目标 Windows 教师电脑和固定数据量后，缓存命中的单班 50 人森林接口 p95 ≤300ms，含前端的打开时间 p95 ≤1s，单次补录可见反馈 ≤1s。它们是待验证的工程目标，不是当前实测结果。页面展示和计分不发大模型请求；OCR、画像批处理与交互任务分别限制并发，不能仅把总并发数调大。

首轮验收数据至少覆盖：有效 0 分、空分、缺考、请假、满分与超满分、重复导入、部分失败、改分、撤销两次、换班、跨学期、转学生、教师覆盖分数、OCR 待核对、仅有总分、历史日期缺失和模型不可用。

本轮完成的是上述审核与设计。现有工作区仍保留原改动；审核中发现的问题尚未因本方案自动修复，Windows 成长树也尚未合入主线。下一批实现应从阶段 0 与事件账本开始，而不是先训练分类器。
