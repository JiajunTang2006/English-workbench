## 你需要补充或确认的内容

1. 封面：正式比赛名称、赛道、学校、团队、成员及指导教师。
2. 教育需求：确认过程性评价、差异化教学和成长反馈是否符合目标教师的实际使用场景；如有访谈或试用材料，可补充对应依据。正文已采用客观项目报告风格，不包含个人经历。
3. 开发贡献：如比赛要求说明每位成员分工、AI 辅助开发工具或原创性声明，请补充真实信息。现稿只介绍可从代码核实的开发技术，不猜测你使用过哪些编辑器或由谁完成了哪些功能。
4. 模型演示：确认实际使用的服务、模型名称、运行模式和演示成功情况。现稿不虚构具体模型表现、单次费用或延迟。
5. 使用与成效：若已经试用，请补充有记录的范围、时间、反馈和测量方法；没有证据时保留正文中的“后续评估计划”。

用户提供的初稿包含“所有工作全部自动化”“零成本、零隐私外泄风险”“自动音频生成”等较强表述。现稿已按当前实现调整；如果这些功能在其他未提供的版本中已经完成，应提供对应源码或演示后再更新完成状态。

排版时可采用 A4、正文 10.5—11 pt、适中的行距和页边距。若表格或截图造成超页，优先精简重复文字、减少截图，而不是压缩字号到难以阅读。最终必须实际编译并核对总页数，封面、目录和参考说明都按总页数预算处理。

Markdown 正文目前不依赖任何缺失图片。若补充截图，建议只选择工作台总览、AI 报告与证据、成长森林三张最能解释功能的画面，每张配一句说明，并确保仅含合成数据。不要把整个屏幕的个人应用和通知一并放入材料。

## 源码运行与现场演示准备

源码仓库包含项目文件和依赖声明，实际运行仍需在评审或演示电脑安装依赖。提交前应由你在独立环境中完整预演；目前不能把已有本机测试等同于“全新机器一键安装已经验证”。

Python 环境的准备顺序可参考：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e vendor/deepseek-harness-upstream/python/sdk-runtime
python -m pip install -e vendor/deepseek-harness-upstream/python/sdk
python -m pip install -r backend/requirements.lock
python launcher.py
```

Windows 使用对应 Python 环境，并以 `.venv\Scripts\activate` 激活。以上是源码准备指引，不是本次新执行的安装验证。若使用 Node Harness 完整路径，还需按仓库中的运行时构建说明准备 Node.js、依赖及构建产物；模型 API 密钥单独配置，不放入仓库。

**文档与实现差异提醒：** 仓库 README 仍含早期“独立 Harness Web 前端”的描述；当前 `launcher.py` 的入口实际由 FastAPI 托管 `/workbench` 页面，Harness 作为后台智能体使用，缺少指定运行时文件时源码启动器可选择 Python Agent 路径。本文以当前代码为准。录制前应确认所用运行模式，不把旧文档中的路径当成已经验证的现场步骤。
